# Лендинг «Журнал смены» — спецификация

**Дата:** 2026-09-24
**Источник идеи:** [`../../../../yc-rfs/product-ideas.md`](../../../../yc-rfs/product-ideas.md), идея 1 «Журнал смены»

## Что это

Одностраничный лендинг, представляющий идею «Журнал смены» — планшет в центре
цеха для учёта простоев тремя касаниями, без облака и серверной части.
Сам журнал (рабочее приложение) в этот проект не входит — только страница,
объясняющая идею и собирающая интерес.

## Аудитория и цель

- **Аудитория.** Мастера смен на других производствах, где учёта простоев,
  брака и передачи смены сейчас нет вообще.
- **Главное действие.** Оставить контакт («хочу попробовать») — страница не
  продаёт готовый продукт, а проверяет интерес.
- **Тон.** Прямой и деловой, «мастер мастеру». Без маркетингового пафоса,
  без личных историй в духе Persona и без ретро-эстетики Game.

## Структура страницы (сверху вниз)

1. **Шапка-проблема.** Заголовок + один абзац: простои, брак и передача смены
   нигде не фиксируются, время просто теряется. Формулировки — из идеи 1 в
   product-ideas.md, без выдумывания новых фактов о читателе.
2. **Как работает: 3 касания.** Оборудование → что случилось → износ/человек
   + длительность. Даётся как схема физического действия мастера у планшета
   (простая инлайн-SVG схема: планшет → 3 подписанных шага), а не как
   скриншот интерфейса — интерфейса пока нет.
3. **Почему это устойчиво.** Один планшет в центре зала (три участка стоят в
   одном зале), без облака и аккаунтов, список причин простоя не придуман
   заранее, а вырастает из реальных записей.
4. **CTA-форма.** Поля: имя, «как связаться» (произвольный текст — телефон,
   telegram, почта). Кнопка отправки собирает значения полей в `mailto:`
   ссылку на почту Александра и открывает почтовый клиент читателя с
   готовой темой и телом письма. Без backend и сторонних форм-сервисов.

## Технический подход

- **Один файл `index.html`** с `<style>` и `<script>` внутри — формат,
  уже дважды доведённый до конца (Persona, Game). Никакой сборки,
  открывается двойным кликом и одинаково работает через file:// и на
  статичном хостинге (GitHub Pages).
- Валидация полей формы — только атрибут `required` на инпутах, без
  дополнительной JS-валидации: полей два, ошибиться в них некуда.
- Приоритет вёрстки — мобильный экран (аудитория открывает с телефона),
  десктоп не должен ломаться, но не является основным сценарием.
- Визуально: тёмный практичный фон, один акцентный цвет для кнопки CTA,
  крупный шрифт без засечек. Без декоративных фото людей.

## Расположение

Проект живёт в собственной папке `StartUp/zhurnal-smeny/` со своим git-
репозиторием (по аналогии с Persona и Game) — так его можно будет опубликовать
и версионировать отдельно от разбора `yc-rfs/`.

```
zhurnal-smeny/
└── index.html   (HTML + <style> + <script>)
```

## Что осознанно не входит

- Рабочий прототип самого журнала (сетка цеха, список причин, сохранение
  записей) — это идея 1 целиком, а не лендинг под неё.
- Backend, сторонние формы, аналитика, cookie-баннеры.
- Секция «Для кого» (портрет мастера смены) и секция с честными
  ограничениями — рассматривались при брейнсторминге и отклонены как
  избыточные для минимальной версии.

## Проверка готовности

- Страница открывается локально (file://) и по вёрстке не ломается на
  ширине телефона (~360px) и на десктопе.
- Кнопка CTA формирует корректную `mailto:`-ссылку с введёнными данными.
- Текст не противоречит фактам из product-ideas.md (идея 1).
